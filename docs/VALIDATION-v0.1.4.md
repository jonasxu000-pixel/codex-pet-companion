# 0.1.4 验证记录

2026-09-30，Windows 本机，150% 显示缩放。验证不关闭承载本次对话的 Codex。

## 问题证据与修复

- 本机计划任务在当天 Codex 启动后已经运行，返回 0，但没有进入助手界面的启动记录。旧版在创建 WPF 前只给桌面窗口 20 秒等待，并未等宠物条件就绪；预检查退出没有日志。新版记录开始/结束及条件，在 Codex 根进程存在、窗口未就绪时设置最多 5 分钟的等待，其余等待也有期限。
- 历史助手记录有数秒内反复“等待桌面”然后退出的情况；旧版用 MainWindowHandle 判断应用是否存在。新版识别并跟踪桌面根进程的 PID/启动时间，窗口隐藏、最小化或重建不等于应用退出。读取宠物状态短暂失败时保留最多 10 秒有效缓存；明确关闭标志清除缓存。
- 本次对话的本地日志保存在两周前的创建日期目录，今天仍在写入。旧版七天目录过滤将它漏掉，界面显示了另一任务。新版按文件最近修改时间发现任务，之后由文件变化通知更新候选；实际界面已能显示本次对话标题及新的工具活动。

## 已验证

- Release 构建、217 项测试通过。回归包括慢窗口启动、宠物延迟就绪、启动等待期限、启动中应用退出、CLI 与桌面区分、旧日期目录中继续工作的任务。
- 最终安装版连续三次关闭助手，再通过 Windows shell 应用激活入口打开 Codex。助手分别在 5.44 / 5.76 / 5.74 秒内显示；未在测试中直接启动助手 EXE 或执行启动任务。各次助手退出后，自有额度查询子进程均为 0。
- 隔离的测试宠物状态文件先关闭、7 秒后写入开启：启动进程确实等待，随后通过预检查。没有修改真实 Codex 配置。
- 真实 GUI：悬停展开且不抢走前台焦点；固定/取消固定、任务下拉选择器可操作；展开详情时额度条位置和尺寸不变。
- 当前用户的计划任务已更新到 0.1.4.0；一个事件触发器，无周期触发器，异常退出最多重试两次。GitHub 仓库仍为私有。
- 收起详情后 60.1 秒采样：32 个逻辑处理器下 CPU 平均约占整机 0.054%；四次工作集为 159.1 / 149.5 / 147.0 / 142.8 MiB，私有内存为 96.8 / 96.6 / 96.6 / 96.6 MiB。结束时自有额度查询子进程为 0，没有为采样清空工作集。

## 验证边界

- 完整 Windows 重启及 Codex 冷启动仍需下一次真实使用确认；本次没有关闭用户的 Codex，也不把现有应用的 shell 再次激活当成冷启动。
- 没有实测数小时内存走势、全部多显示器组合或真实断网恢复。短时采样不等于长期无泄漏证明。
- 保留无全天驻留进程的设计：直接启动内部 EXE 绕过系统激活、或很久之后才开启宠物等入口，仍可能需要手动启动助手。本版不宣称覆盖所有入口。
- 任务状态来自最近本地日志，不能读取模型内部思维，也不能用日志静默证明卡死。
